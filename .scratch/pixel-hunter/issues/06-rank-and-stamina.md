# 06: Rank and Stamina via statusLine script

**What to build:** An optional Claude Code statusLine script that records, per terminal, the context window left and the model name (stripping control and bidi characters). The Hunter rows and the pane data read those records. Rank shows as a letter grade plus the model, like `[A] Opus 5.5`, from an editable grade table (Fable S, Opus A, Sonnet B, Haiku C, else `?` with the program name). Stamina is a bar: blue at 50% and up, cream from 20% to 50%, peach below 20%, with no blinking. It shows `—` with no data and is marked `old` past a freshness limit. Nothing is ever estimated. The README explains the one-time setup.

## Comments

- Done in the live config, then `scripts/sync.sh`. New and changed in `mods/pixel-hunter/`:
  - `statusline.mjs`: the optional Claude Code statusLine script (plain Node, no Herdr imports). It reads the session JSON on stdin and writes `{ v: 1, app: "claude-code", terminal, session, model, modelId, left, at }` to `<appHome>/data/pixel-hunter/sessions/<HC_TERMINAL_ID>.json` (`$PIXEL_HUNTER_SESSIONS` overrides the folder, `$HERDR_APP_HOME` the Herdr home). `model` is `model.display_name` (else `model.id`). `left` is `context_window.remaining_percentage`, else `100 - used_percentage`, else null. It is never computed from token counts. C0/C1 controls, DEL and the bidi marks/embeddings/overrides/isolates are stripped and text is capped at 80 chars. It writes via a temp file and rename (falling back to an in-place write on Windows), and only when values change or the old record is a minute old, so a busy session doesn't redraw the window on every message. A record with neither a model nor a number isn't written, so bad input keeps the last good record. Outside a Herdr terminal (no `HC_TERMINAL_ID`, or one that isn't a plain id) it writes nothing. It prints `Opus 5.5 · 62% context left`, or nothing with `--quiet` (for chaining from the user's own status line). It always exits 0.
  - `rank.json`: the grade table `{ "grades": { "Fable": "S", "Opus": "A", "Sonnet": "B", "Haiku": "C" }, "staleAfterSeconds": 300 }`. The first key found as whole word(s) in the model name wins, case-insensitive, so `claude-sonnet-5-5` grades B too. A broken file or entry falls back to `RANKS` in `hunt.js`.
  - `hunt.js`: new inputs `sessions` (`{ [terminal]: record }`) and `ranks` (rank.json), and `app` on panes. Each Hunter gets `rank: { grade, label, text }` and `stamina: { percent, level: high|mid|low, stale, staleAt }`. `program` stays. Exports `RANKS`, `STAMINA_HIGH` (50), `STAMINA_LOW` (20), `rankTable`, `gradeFor`, `staminaLevel`. The percent is rounded first and the level comes from the rounded value, so the bar and the number never disagree (49.6 → 50 → blue). A record is ignored without a finite `at`, or when its `app` differs from the pane's reported app (an old Claude record in a terminal now running codex).
  - `sessions.js` (Herdr adapter): `startSessions(self, cx)` reads `rank.json` once per mod load (saving it reloads the mod, so edits show at once), creates the sessions folder and loops `watchFolder` → re-read all records → `cx.notify()` only if they changed. It starts the watch before reading, so a write during the read isn't missed. No timer.
  - `main.js` now runs a per-role `init` (`INITS`). The sidebar's init starts the session reader (not in demo mode). `world(self, now)` passes `self.sessions`/`self.ranks` and each pane's `app`.
  - `sidebar.js`: the 10 s HP one-shot is now one "wake" one-shot armed for the earliest need, either `now + HP_TICK_MS` while HP wears or the next fresh record's `staleAt + 1`. An earlier need supersedes a later armed one (the later one does nothing when it fires). Nothing is armed with nobody Hunting and no fresh record.
  - `areas.js`: line 2 of a Hunter row is now a grade tag (12 px, `canvas` text on `accent`, `dim` for `?`), the Rank label, the branch if different, then Stamina on the right: a 46 px bar (2 px `border` frame on `canvas`, 8 px fill in `working` / `foreground` / `blocked`), or `STA —` in `dim`. A stale record shows `old` (12 px `dim`) and a `dim` fill. Exports `gradeBadge`, `staminaView` for ticket 07's pane headers.
  - `demo.js`: `demoSessions(now)` gives the mock's Ranks (Opus 72, Sonnet 24, codex `?`/`—`, an old Opus 41, Fable 15).
  - Tests: `test/hunt.test.js` gets 6 cases (grade table and ids, unknown model and no-record `?` + program, a changed table and the shipped `rank.json`, levels at 50/49.6/49.4/20/19.6/19.4, `—` for no record / no number / bad record / other app, stale at the exact limit and with a custom limit). `test/statusline.test.js` has 6 black-box cases that spawn the script with env and stdin: the expected record, remaining vs used vs none, control/bidi stripping (written and printed), malformed inputs (exit 0, no stderr, last record kept), no terminal / path-like terminal, `--quiet` and the once-a-minute rewrite. 34/34 pass.
- README: a "Rank and Stamina" section with the one-time `statusLine` setup (`node ~/.config/herdr-app/mods/pixel-hunter/statusline.mjs`, `refreshInterval: 60`), `--quiet` chaining, and the grade table. I did **not** touch `~/.claude/settings.json`; the user decides.
- Decisions to review:
  - An ungraded model with a record shows `[?] <model name>` (e.g. `[?] Mythos 1`), not the program name, so you can see which name to add to `rank.json`. With no record it's `[?] <program>` as the spec says.
  - The grade shows as the mock's tag (`A` on mint), not literal brackets. `rank.text` is `"[A] Opus 5.5"` for places that want plain text.
  - Freshness limit 5 min, editable as `staleAfterSeconds`. Claude Code (2.1.318 here) runs the script only when the conversation changes, unless `statusLine.refreshInterval` (seconds) is set, so the README sets 60. Without it an idle session goes `old` after 5 min.
  - Records live in `<appHome>/data/pixel-hunter/sessions/`. Herdr lists `data/` as its own bookkeeping (per-mod `store.json`), and a subfolder doesn't collide. Records of closed terminals aren't pruned. They go stale, and they only show when a live agent pane has that terminal id.
